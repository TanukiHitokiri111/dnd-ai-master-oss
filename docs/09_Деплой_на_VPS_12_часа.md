ЭТАП 9. Деплой на VPS (⏱ 1–2 часа)

9.1. Подготовка сервера (Ubuntu 22.04, от 1 ГБ RAM)

ssh root@ВАШ_IP_СЕРВЕРА
apt update && apt upgrade -y
apt install -y python3.11 python3.11-venv nginx ufw

ufw allow OpenSSH
ufw allow 'Nginx Full'
ufw enable    # подтвердить: y
bash


Если у облачного провайдера есть своя панель-firewall (Security Groups) — откройте порты 80 и 443 и там.


9.2. Код и окружение

С локальной машины (обратите внимание на --exclude .env — не затираем серверные секреты локальными):

rsync -av --exclude venv --exclude .git --exclude .env --exclude __pycache__ \
  ~/projects/dnd_ai/rpg_backend/ root@ВАШ_IP_СЕРВЕРА:/opt/rpg_backend/
bash


На сервере:

mkdir -p /opt/rpg_backend   # если rsync ругался на отсутствие папки — повторите rsync
cd /opt/rpg_backend
python3.11 -m venv venv
./venv/bin/pip install -r requirements.txt
nano .env     # вставьте: OPENAI_API_KEY=***  и  DEBUG=false
chown -R www-data:www-data /opt/rpg_backend
chmod 600 /opt/rpg_backend/.env
bash


9.3. Systemd: /etc/systemd/system/rpg-backend.service (🔴 исправлен EnvironmentFile-баг)

[Unit]
Description=D&D AI Master Backend
After=network.target

[Service]
Type=simple
User=www-data
Group=www-data
WorkingDirectory=/opt/rpg_backend
# EnvironmentFile НАМЕРЕННО убран:
# systemd съедает кавычки в CORS_ORIGINS=["*"] → pydantic падал бы при старте.
# pydantic-settings сам читает .env из WorkingDirectory — надёжнее.
ExecStart=/opt/rpg_backend/venv/bin/gunicorn app.main:app \
  --workers 1 \
  --worker-class uvicorn.workers.UvicornWorker \
  --bind 127.0.0.1:8000 \
  --access-logfile - --error-logfile -
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
ini


Два важных момента: --workers 1 (in-memory история!) и --bind 127.0.0.1:8000 (наружу смотрит только Nginx).


systemctl daemon-reload
systemctl enable --now rpg-backend
systemctl status rpg-backend        # Active: active (running)
curl http://127.0.0.1:8000/health   # {"status":"healthy",...}
journalctl -u rpg-backend -n 50 --no-pager   # логи, если что-то не так
bash


9.4. 🔴 DNS — обязательно ДО certbot

В панели вашего регистратора домена создайте A-запись: your-domain.com → ВАШ_IP_СЕРВЕРА.


Проверка с локальной машины (подождите 5–30 минут распространения):

ping -c1 your-domain.com
# в ответе должен быть IP вашего сервера. Если нет — certbot НЕ запускать, ждите.
bash


9.5. Nginx: /etc/nginx/sites-available/rpg

server {
    listen 80;
    server_name your-domain.com;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 300s;   # AI может думать долго
    }
}
nginx


ln -s /etc/nginx/sites-available/rpg /etc/nginx/sites-enabled/
nginx -t && systemctl reload nginx
bash


9.6. SSL (бесплатный сертификат)

apt install -y certbot python3-certbot-nginx
certbot --nginx -d your-domain.com
curl https://your-domain.com/health   # {"status":"healthy",...}
bash


После этого: в app_config.dart → baseUrl = 'https://your-domain.com' → flutter build apk --release → установить заново. HTTP/IP в network_security_config.xml для продакшена больше не нужен (HTTPS работает всегда).


9.7. Процедура обновления (когда измените код)

# локально:
rsync -av --exclude venv --exclude .git --exclude .env --exclude __pycache__ \
  ~/projects/dnd_ai/rpg_backend/ root@ВАШ_IP:/opt/rpg_backend/
# на сервере:
chown -R www-data:www-data /opt/rpg_backend
systemctl restart rpg-backend
journalctl -u rpg-backend -f    # смотрим логи запуска
