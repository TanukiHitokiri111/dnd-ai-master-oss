ЭТАП 10. CI/CD (⏱ 20 мин)

Файл .github/workflows/build.yml в корне монорепозитория (пути rpg_backend/ и rpg_client/ теперь совпадают со структурой):

name: Build & Test

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  test-backend:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: '3.11'
      - name: Install dependencies
        run: pip install -r rpg_backend/requirements.txt
      - name: Lint
        run: cd rpg_backend && ruff check app/
      - name: Run tests
        # conftest.py сам подставит фейковый OPENAI_API_KEY
        run: cd rpg_backend && pytest -v

  build-flutter:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with:
          distribution: 'temurin'
          java-version: '17'
      - uses: subosito/flutter-action@v2
        with:
          flutter-version: '3.24.3'
          channel: 'stable'
      - name: Dependencies + codegen
        run: |
          cd rpg_client
          flutter pub get
          dart run build_runner build --delete-conflicting-outputs
      - name: Analyze
        run: cd rpg_client && flutter analyze
      - name: Tests
        run: cd rpg_client && flutter test
      - name: Build APK (debug-подпись, только для проверки сборки)
        run: cd rpg_client && flutter build apk --release
      - uses: actions/upload-artifact@v4
        with:
          name: app-release
          path: rpg_client/build/app/outputs/flutter-apk/app-release.apk
yaml


⚠️ CI-сборка APK упадёт без key.properties? Нет — блок if (keystorePropertiesFile.exists()) в build.gradle пропускает подпись, и Gradle собирает release с debug-подписью. Именно поэтому эта проверка в CI безопасна и не требует секретов.
