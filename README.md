# D&D AI Master

Самохостящийся текстовый RPG с AI-мастером поднимает полноценную партию в Dungeons & Dragons 5e: мастер ведёт сцену, помнит историю, бросает проверки, выдаёт лут и не предлагает игроку готовых вариантов действий.

Разворачивается одной командой на своём сервере. Работает с любым OpenAI-совместимым провайдером — от облачных API до локальной модели в Ollama.

---

## Что умеет

**Игровой процесс**
- Чат-отыгрыш с мастером: описание сцен, диалоги NPC, реакции на действия игрока
- Память: мастер помнит события кампании, отношения с NPC, принятые решения
- Броски d20 с модификаторами, проверки навыков, бой по инициативе
- Инвентарь, золото, экипировка, заклинания
- Прокачка уровней, выбор архетипа, многорасовые персонажи

**Мультиплеер**
- Совместные сессии до нескольких игроков в одной кампании
- Групповой чат, друзья, приглашения

**Мир**
- 20+ готовых миров: техно-фэнтези, стимпанк, дизельпанк, постапокалипсис, космос, Warhammer 40k и другие
- Расы, классы, предыстории и навыки под каждый мир
- Генерация картинок персонажей, NPC и сцен через любой совместимый провайдер картинок

**Для владельца сервера**
- Полная база SQLite в одном каталоге — резервная копия = копия папки
- Опциональная интеграция платежей (ЮKassa) — выключена, пока не заполните ключи
- Подробные логи, Swagger при `DEBUG=true`

## Быстрый старт

Нужен только Docker.

```bash
git clone https://github.com/TanukiHitokiri111/dnd-ai-master-oss.git
cd dnd-ai-master-oss
./install.sh
```

Скрипт спросит ключ провайдера, сгенерирует секрет, соберёт образ и запустит сервис. Через минуту игра доступна на `http://localhost:8000`.

### Вручную, если не любите скрипты

```bash
cd rpg_backend
cp .env.example .env
# откройте .env и заполните LLM_API_KEY, LLM_API_BASE_URL, MODEL, JWT_SECRET
docker compose up -d --build
```

## Настройка провайдера

Подходит любой сервис с OpenAI-совместимым `/v1/chat/completions`.

| Провайдер | `LLM_API_BASE_URL` | `MODEL` (пример) |
|---|---|---|
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| OpenRouter | `https://openrouter.ai/api/v1` | `deepseek/deepseek-chat` |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| Ollama (локально) | `http://host.docker.internal:11434/v1` | `qwen2.5:14b` |
| LM Studio (локально) | `http://host.docker.internal:1234/v1` | `local-model` |

Для локальной модели ключ можно указать любой (`ollama`, `none`) — он не проверяется.

Хотите полностью бесплатно и без интернета: поставьте [Ollama](https://ollama.com), скачайте модель на 14–32 млрд параметров (`ollama pull qwen2.5:14b`) и укажите её в `.env`. Русский язык у Qwen и Gemma заметно лучше, чем у мелких Llama.

## Переменные окружения

Полный список с пояснениями — в `rpg_backend/.env.example`. Главное:

| Переменная | Назначение |
|---|---|
| `LLM_API_KEY` | ключ провайдера (обязательно) |
| `LLM_API_BASE_URL` | адрес API (обязательно) |
| `MODEL` | название модели (обязательно) |
| `JWT_SECRET` | подпись токенов, 32+ символа (обязательно) |
| `ADMIN_USER_IDS` | ID админов через запятую |
| `MAX_HISTORY_LENGTH` | глубина контекста в сообщениях |
| `CORS_ORIGINS` | домены, которым разрешены запросы |
| `YOOKASSA_*` | платежи, необязательно |
| `DEBUG` | `true` открывает `/docs` и подробные логи |

Свой ID для админки видно в `/api/v1/auth/me` после регистрации.

## Куда кладутся данные

Все состояние — в `rpg_backend/data/`:

- `rpg.db` — база: пользователи, персонажи, история чатов
- `appearance/`, `scenes/` — сгенерированные картинки

Каталог смонтирован в контейнер как volume. Резервная копия — обычное копирование папки. При обновлении пересобирайте образ, данные не тронутся.

## Разработка

**Бэкенд**

```bash
cd rpg_backend
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload
```

Тесты:

```bash
cd rpg_backend && pytest
```

**Клиент (Flutter)**

```bash
cd rpg_client
flutter pub get
flutter run -d chrome --dart-define=API_BASE_URL=http://localhost:8000
```

Сборка веб-версии:

```bash
flutter build web --base-href / --dart-define=API_BASE_URL=
```

Пустой `API_BASE_URL` означает «тот же хост» — удобно, когда клиент и API за одним прокси.

```
rpg_client/            Flutter-клиент (веб + Android)
docs/                  внутренние заметки по архитектуре
```
