# Участие в разработке

## Баг-репорт

Опишите: что делали, что ожидали, что получилось. Приложите логи контейнера:

```bash
cd rpg_backend && docker compose logs --tail 100
```

и, если дело в игре, — последние сообщения чата и название мира.

## Идея или крупное изменение

Сначала откройте issue с описанием. Иначе есть риск, что PR разойдётся
с архитектурой проекта и его придётся отклонять по техническим причинам,
а не по существу.

## Pull request

1. Форкните репозиторий и создайте ветку от `main`.
2. Держите изменения сфокусированными: одна задача — один PR.
3. Бэкенд: `cd rpg_backend && pytest` должен быть зелёным.
4. Стиль Python: `ruff check app`.
5. Не добавляйте в код ключи, пароли, свои домены и IP — только через `.env`.
6. Обновите README, если меняете поведение или настройки.

## Чего не принимаем

- Секреты и токены в коде или в истории коммитов.
- Отключение проверок безопасности ради «чтобы работало».
- Массовые переформатирования файлов без содержательных изменений.
- Контент, нарушающий закон или права третьих лиц.

## Лицензия вклада

Отправляя PR, вы соглашаетесь, что ваш вклад распространяется под MIT,
как и весь проект.
